# nn 언어 명세

상태: 초안(Draft), 현재 구현을 기술함.

이 문서는 `nn` 언어를 명세한다. `nn`은 컴파일 타임에 텐서 모양(shape)을
검사하는, 이름이 붙은 *플로우(flow)* 단위로 심층 신경망 모델을 기술하기 위한
도메인 특화 언어이다.

> 이 문서는 영어 원본 [`../specification.md`](../specification.md)의 한국어
> 번역본이다. 두 문서가 충돌할 경우 영어 원본을 정본(authoritative)으로 한다.

## 1. 범위 (Scope)

이 명세는 **언어 핵심(language core)**을 정의한다:

- 어휘 구조(lexical structure),
- 모듈(소스 파일) 구조 및 임포트,
- 선언(declaration),
- 식(expression) 및 파이프라인 연산자,
- 타입 시스템,
- 사이즈 시스템,
- 적합한 구현이 수행하는 정적 검사.

도구(tooling) 동작 — 커맨드라인 인터페이스, 코드 생성, 파라미터/비용 분석,
에디터 연동 — 은 이 문서의 **범위 밖**이다.

문법으로는 인식되지만 아직 완전히 정의되지 않은 기능, 그리고 모호하거나 충분히
명세되지 않은 사항은 [`draft-features.md`](./draft-features.md)에 별도로
기록하며, 이 명세의 일부가 **아니다**.

## 2. 적합성 (Conformance)

이 문서에서 "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD",
"SHOULD NOT", "RECOMMENDED", "MAY", "OPTIONAL" 라는 핵심어는 RFC 2119에 기술된
대로 해석한다.

**적합한 프로그램(conforming program)**은 이 명세의 모든 "MUST"/"SHALL" 요구사항을
충족하는 소스 파일들의 나열이다.

**적합한 구현(conforming implementation)**은 다음을 지켜야 한다:

- 모든 적합한 프로그램을 받아들여야 한다(MUST).
- "MUST"/"SHALL" 요구사항을 위반하는 모든 프로그램을 거부해야 하며(MUST), 그
  위반을 해당 소스 위치를 가리키는 진단(diagnostic)으로 보고해야 한다(SHOULD).
- `draft-features.md`에 나열된 어떤 구성요소도 요구해서는 안 된다(MUST NOT).

진단은 치명적이지 않은 보고이다. 구현은 하나의 프로그램에 대해 둘 이상의 진단을
보고할 수 있으며(MAY), 복구 가능한 오류 이후에도 가능한 한 검사를 계속해야
한다(SHOULD).

## 3. 표기법 (Notation)

문법은 EBNF 유사 형식으로 제시한다:

- `"x"` 는 리터럴 텍스트 `x` 를 나타낸다.
- `a b` 는 `a` 다음에 `b` 가 오는 것을 나타낸다.
- `a | b` 는 선택을 나타낸다.
- `a?` 는 `a` 가 0개 또는 1개임을 나타낸다.
- `a*` 는 `a` 가 0개 이상임을 나타낸다.
- `a+` 는 `a` 가 1개 이상임을 나타낸다.
- `( … )` 는 묶음을 나타낸다.

어휘 패턴은 편의상 정규 표현식으로 제시하는 경우가 있다.

## 4. 어휘 구조 (Lexical Structure)

### 4.1 소스 텍스트

소스 파일은 유니코드 문자의 나열이다. 토큰은 *공백(whitespace)*과
*주석(comment)*으로 구분되며, 이들은 토큰 구분자 역할 외에는 의미가 없다.
공백은 스페이스, 탭, 줄바꿈, 그리고 U+FEFF, U+2060, U+200B, U+00A0 문자를
포함한다.

### 4.2 주석

```
comment ::= "#" /[^\n]*/
```

주석은 `#` 로 시작하여 그 줄의 끝까지 이어진다. 주석은 공백이 허용되는 어디에나
올 수 있다(MAY). 선언 바로 앞에 오는 주석은 그 선언의 *선행 주석(leading
comment)*이다. 적합한 구현은 문서화 목적으로 이를 선언에 연관 지을 수
있으나(MAY), 주석은 의미론적 효력이 없다.

### 4.3 식별자

```
identifier ::= /[A-Za-z_$][A-Za-z0-9_]*/
```

식별자는 ASCII 문자, `_`, 또는 `$` 로 시작해야 하며(MUST), 그 뒤에는 ASCII 문자,
숫자, `_` 가 온다. 식별자는 대소문자를 구분한다.

식별자는 플로우 이름, 사이즈 이름, 값 이름, 그리고 텐서 타입 이름 `Tensor` 에
쓰인다. 이 언어에는 일반적인 키워드 집합이 없다. `Tensor` 와 빌트인 플로우 이름
`Trainable`(§9.3)만이 예약된 의미를 가지며, 이들은 문맥에 따라 인식된다.

### 4.4 숫자

```
number ::= /-?[0-9]+(\.[0-9]+)?/
```

숫자 리터럴은 사이즈 리터럴(§8)로만 등장한다. 적합한 프로그램은 음이 아닌 정수
사이즈 리터럴을 사용해야 한다(SHOULD). 음수 및 분수 사이즈 리터럴의 처리는
명세되지 않았다(`draft-features.md` 참고).

### 4.5 문자열 리터럴

```
string ::= "'" /([^'\\]|\\.)*/ "'"
         | "\"" /([^"\\]|\\.)*/ "\""
```

문자열 리터럴은 짝이 맞는 작은따옴표(`'`) 또는 큰따옴표(`"`)로 구분된다.
백슬래시는 이스케이프 시퀀스를 도입한다. 문자열 리터럴은 호출 인자(§6.5)와 임포트
대상(§5.3)으로만 등장한다.

## 5. 모듈 (Modules)

### 5.1 소스 파일

```
source_file ::= ( import_statement | declaration )*
```

소스 파일은 임포트 문과 선언이 임의의 순서로 나열된 것이다. 각 소스 파일은 그
위치로 식별되는 하나의 모듈이다.

### 5.2 최상위 이름

모듈의 최상위 이름은 그 선언(§6)의 이름과 그 임포트(§5.3)가 도입한 이름의
집합이다. 하나의 모듈 안에서 모든 최상위 플로우 이름은 유일해야 한다(MUST).

### 5.3 임포트

```
import_statement ::= "import" "{" ident_list? "}" "from" string
ident_list       ::= identifier ( "," identifier )* ","?
```

임포트 문은 다른 모듈의 선택된 최상위 플로우 이름을, 같은 이름으로 임포트하는
모듈에서 사용할 수 있게 한다. 문자열은 *임포트 대상(import target)*이며 임포트하는
모듈의 위치를 기준으로 해석되는 경로 참조여야 한다(MUST).

다음 규칙이 적용된다:

- 대상은 존재하는 모듈로 해석되어야 한다(MUST). 그렇지 않으면 그 프로그램은
  유효하지 않다.
- 임포트되는 각 이름은 대상 모듈의 최상위 플로우 이름이어야 한다(MUST). 대상
  모듈이 제공하지 않는 이름을 임포트하는 것은 유효하지 않다.
- 임포트된 이름은 플로우 이름이 기대되는 곳 어디에서나(§6.6) 사용할 수 있으며,
  대상 모듈에서와 동일한 플로우를 가리킨다.

임포트 목록은 비어 있을 수 있으며(MAY), 이 경우 문은 대상 모듈이 존재할 것만을
요구한다.

## 6. 선언 (Declarations)

### 6.1 문법

```
declaration            ::= identifier size_decl_list? argument_list
                           ( ":" type )? body?
size_decl_list         ::= "[" ident_list "]"
argument_list          ::= "(" argument_decl_list? ")"
argument_decl_list     ::= argument_decl ( "," argument_decl )* ","?
argument_decl          ::= identifier ":" type
body                   ::= "=" "|>"? expression ( "|>" expression )*
```

선언은 *플로우(flow)*를 정의한다. 플로우는 입력 텐서로부터 출력 텐서로의, 이름이
붙은 변환이다.

### 6.2 사이즈 선언 목록

플로우 이름 뒤에 오는 선택적 `[ … ]` 목록은 선언 전체에서 유효 범위에 있는
*사이즈 변수(size variable)*(§8.3)를 선언한다. 선언된 사이즈 이름은 하나의 선언
안에서 서로 구별되어야 한다(MUST).

### 6.3 인자 목록

인자 목록은 플로우의 입력 *값(value)*을 선언한다. 각 인자는 값 이름을 텐서 타입에
바인딩한다. 인자 값 이름은 하나의 선언 안에서 서로 구별되어야 한다(MUST).

인자 타입에 나타나지만 사이즈 선언 목록에는 없는 사이즈 이름은, 그 첫 등장 시점에
플로우의 사이즈 변수로 **암시적으로 선언된다**(§8.3).

### 6.4 반환 타입

선택적 `: type` 은 플로우의 출력 타입을 명시한다.

- 본문이 없는 선언(§6.7)에서는 반환 타입이 필수이며(REQUIRED) 플로우의 출력
  타입을 정의한다.
- 본문이 있는 선언에서는 출력 타입이 본문의 마지막 식(§6.6)의 타입이다. 명시적
  반환 타입 표기와 추론된 본문 타입 사이의 관계는 이 명세에서 정의하지 않는다
  (`draft-features.md` 참고).

반환 타입에 나타나는 모든 사이즈 이름은 이미 유효 범위에 있어야 한다(MUST, §8.3).
반환 타입은 새로운 사이즈 변수를 도입해서는 안 된다(MUST NOT).

### 6.5 본문과 파이프라인

본문은 `=` 다음에, *파이프라인 연산자(pipeline operator)*인 `|>` 로 구분된 하나
이상의 식이 오며, 선행 `|>` 는 선택적이다(OPTIONAL).

파이프라인은 한 단계에서 다음 단계로 값을 전달한다:

- 각 단계의 결과는 다음 단계 호출의 **선행 인자(leading argument)**로 공급되며,
  그 호출의 명시적 인자보다 앞에 놓인다.
- 튜플 식(§7.2)인 단계는 여러 값을 산출하며, 이는 순서대로 다음 단계의 여러 선행
  인자가 된다.
- 첫 단계를 제외한 모든 단계는 호출 식(§7.1)이어야 한다(MUST).
- 본문이 선행 `|>` 로 시작하면 첫 단계는 호출 식이어야 한다(MUST). 그렇지 않으면
  첫 단계는 임의의 식일 수 있으며(MAY), 그 값이 파이프라인의 시작 값이 된다.

플로우의 출력 타입은 마지막 단계의 타입이다.

### 6.6 본문 내 이름 유효 범위

본문 안에서는 다음 이름들이 유효 범위에 있다:

- 플로우의 사이즈 변수(§6.2, §6.3),
- 플로우의 인자 값 이름,
- 대입 식(§7.3)으로 도입된 값 이름.

값 이름은 사용되는 지점보다 앞에서 정의되어야 한다(MUST). 정의되기 전에 값을
사용하는 것은 유효하지 않다. 선언되지 않은 값 이름, 사이즈 이름, 플로우 이름의
사용은 유효하지 않다.

### 6.7 시그니처 전용 선언

선언은 본문을 생략할 수 있다(MAY). 그러한 선언은 *시그니처 전용(signature-only)*
플로우이다. 즉, 계산을 정의하지 않고 플로우의 사이즈 변수, 인자 타입, 반환 타입만
선언한다. 시그니처 전용 선언은 반환 타입을 제공해야 한다(MUST, §6.4). 시그니처
전용 선언은 외부에서 제공되는 연산자를 기술하는 데 사용된다.

## 7. 식 (Expressions)

```
expression ::= call_expression
             | tuple_expression
             | assignment_expression
             | identifier_expression
             | string_expression
```

### 7.1 호출 식

```
call_expression ::= identifier size_type? argument_list_call
argument_list_call ::= "(" ( expression ( "," expression )* ","? )? ")"
size_type          ::= "[" size ( "," size )* ","? "]"
```

호출 식은 식별자가 가리키는 플로우를 적용한다. 선택적 `[ … ]` 는 *사이즈
인자(size argument)*(§8)를 공급하고, 괄호 목록은 값 인자를 공급한다. 두 목록 모두
비어 있을 수 있다(MAY).

호출 적용은 다음을 요구한다(§9):

- 피호출자(callee)는 유효 범위에 있는 플로우 이름이어야 한다(MUST) — 로컬 선언,
  임포트된 이름, 또는 빌트인(§9.3),
- 값 인자의 개수는 피호출자의 인자 개수와 같아야 한다(MUST),
- 사이즈 인자가 공급될 때, 그 개수는 피호출자가 선언한 사이즈 변수 개수와 같아야
  한다(MUST).

### 7.2 튜플 식

```
tuple_expression ::= plain_expression ( "," plain_expression )+
```

튜플 식은 둘 이상의 값을 묶는다. 튜플은 하나의 파이프라인 단계에 여러 값을
공급하는 데 사용된다(§6.5). `plain_expression` 은 호출, 식별자, 또는 문자열
식이다.

### 7.3 대입 식

```
assignment_expression ::= identifier "=" plain_expression
```

대입은 값 이름을 우변 식의 값에 바인딩하고, 그 이름을 본문의 이후 식에서 사용할 수
있게 한다(§6.6). 바인딩되는 이름은 자신의 우변 식 안에서 참조되어서는 안 된다
(MUST NOT).

### 7.4 식별자 식

식으로 사용된 식별자는 유효 범위에 있는 값(§6.6)을 가리키며, 그 값의 타입으로
평가된다.

### 7.5 문자열 식

호출 인자로 사용된 문자열 리터럴은 *메타데이터*(예: 파라미터 이름)이다. 문자열
인자는 텐서 피연산자가 아니다. 즉, 모양 검사에 참여하지 않으며, 아리티(arity)
목적상 피호출자의 값 인자 개수에 포함되지 않는다(§9.1).

## 8. 사이즈 시스템 (Size System)

### 8.1 사이즈

```
size      ::= size "^" size
            | size "*" size
            | size "/" size
            | size "+" size
            | size "-" size
            | "(" size ")"
            | identifier
            | number
```

*사이즈(size)*는 텐서 모양의 한 차원을 기술하는 기호적(symbolic)이고 음이 아닌
정수 식이다. 사이즈는 사이즈 변수(§8.3), 정수 리터럴, 그리고 아래의 산술
연산자로 구성된다.

### 8.2 연산자와 우선순위

사이즈 연산자는 결합 강도가 높은 것부터 낮은 순으로 다음과 같다:

1. `^` (거듭제곱),
2. `*` 와 `/` (곱셈, 나눗셈),
3. `+` 와 `-` (덧셈, 뺄셈).

`*`, `/`, `+`, `-` 는 좌결합(left-associative)이고, `^` 도 좌결합이다. 괄호는
우선순위를 재정의한다. 두 사이즈는 통상의 정수 산술 하에서 같은 값을 나타낼 때
같다(예: `A * 2` 와 `2 * A` 는 같고, `A + B` 는 `B + A` 와 같다).

### 8.3 사이즈 변수와 유효 범위

사이즈 변수는 다음에 의해 도입된다:

- 사이즈 선언 목록(§6.2), 또는
- 인자 타입에서의 첫 등장(§6.3).

사이즈 변수는 그것을 도입하는 선언으로 유효 범위가 한정된다. 반환 타입이나 본문에
사용된 사이즈 이름은 이미 유효 범위에 있어야 한다(MUST). 그러한 위치는 새로운
사이즈 변수를 도입해서는 안 된다(MUST NOT).

### 8.4 사이즈 인자와 추론

플로우의 사이즈 변수는 각 호출 지점에서 다음으로 결정된다:

- `[ … ]` 안의 명시적 사이즈 인자(§7.1), 그리고/또는
- 값 인자의 모양으로부터의 추론(§9.2).

호출이 해석된 후, 피호출자의 모든 사이즈 변수가 결정되어야 한다(MUST). 결정될 수
없는 사이즈 변수는 *모호(ambiguous)*하며 그 호출을 유효하지 않게 만든다.

## 9. 타입 시스템과 검사 (Type System and Checking)

### 9.1 타입

유일한 타입은 텐서 타입이다:

```
type ::= "Tensor" size_type?
```

텐서 타입은 *모양(shape)*을 가진다. 모양은 사이즈(§8)의 순서 있는 목록이다. 모양은
비어 있을 수 있으며(`Tensor`), 이 명세의 목적상 랭크/모양이 명시되지 않은 텐서를
나타낸다. 스칼라 타입이나 비-텐서 타입은 없다.

두 텐서 타입은 모양의 길이가 같고 대응되는 사이즈가 같을 때(§8.2) 같다.

### 9.2 인자 매칭과 모양 전파

호출을 검사할 때, 각 값 인자의 타입은 피호출자의 대응되는 선언된 인자 타입과
대조된다:

- **첫 번째** 값 인자(파이프라인으로 전달된 값 포함)의 모양은 피호출자가 요구하는
  차원 외에 추가적인 **선행(leading)** 차원을 가질 수 있다(MAY). 요구되는 후행
  차원은 피호출자가 선언한 모양과 일치해야 하며(MUST), 추가된 선행 차원은
  그대로 전달되어 호출 결과 모양의 앞에 붙는다.
- **그 이후의** 모든 값 인자에서는 모양의 길이가 피호출자가 선언한 인자 모양의
  길이와 같아야 하고(MUST), 대응되는 사이즈가 일치해야 한다(MUST).

이 매칭을 통해 피호출자의 사이즈 변수는 인자 모양으로부터 도출된 구체적 사이즈에
바인딩된다. 이 바인딩들은 명시적 사이즈 인자와 함께 서로 일관되어야 한다(MUST).
일관되지 않은 바인딩(같은 사이즈 변수가 서로 다른 두 값으로 강제됨)은 그 호출을
유효하지 않게 만든다.

호출의 결과 타입은 피호출자의 반환 타입에서 사이즈 변수를 바인딩된 사이즈로
치환한 것이며, 전달된 선행 차원이 있으면 그 앞에 붙는다.

### 9.3 `Trainable` 빌트인

`Trainable` 은 임포트 없이 모든 모듈에서 사용 가능한 빌트인 플로우이다. 호출
`Trainable[s1, …, sn]('name')` 은 타입 `Tensor[s1, …, sn]` 을 가진다. 즉, 사이즈
인자가 그 모양이 되고, 문자열 인자가 학습 가능한 파라미터의 이름을 지정한다.
적합한 프로그램은 `Trainable` 을 이 빌트인 외의 다른 의미로 재선언해서는 안 된다
(MUST NOT).

### 9.4 플로우 호출 그래프

플로우 호출 관계는 비순환(acyclic)이어야 한다(MUST):

- 플로우는 자기 자신을 직접 호출해서는 안 된다(MUST NOT) — 자기 재귀는 유효하지
  않다.
- 플로우들의 집합은 호출의 순환을 이루어서는 안 된다(MUST NOT) — 상호 재귀는
  유효하지 않다.

### 9.5 적합한 구현이 반드시 거부해야 하는 조건

적합한 구현은 다음 중 어느 하나라도 발생하는 프로그램을 거부해야 한다(MUST):

1. 구문 오류(예상치 못하거나 인식되지 않는 토큰).
2. 한 모듈 안에서 두 최상위 플로우가 이름을 공유함(§5.2).
3. 존재하는 모듈로 해석되지 않는 임포트 대상(§5.3).
4. 대상 모듈이 제공하지 않는 임포트 이름(§5.3).
5. 선언되지 않은 플로우 이름, 값 이름, 또는 사이즈 이름의 사용(§6.6, §8.3).
6. 값이 정의되기 전에 사용됨(§6.6).
7. 첫 단계가 아닌 파이프라인 단계가 호출 식이 아니거나, 선행 `|>` 본문의 첫
   단계가 호출 식이 아님(§6.5).
8. 값 인자 개수가 피호출자의 개수와 다른 호출(§7.1, §9.1).
9. 사이즈 인자가 공급될 때, 명시적 사이즈 인자 개수가 피호출자의 개수와 다른
   호출(§7.1).
10. 인자와 피호출자가 선언한 인자 타입 사이의 모양 불일치(§9.2).
11. 일관되지 않은 사이즈 변수 바인딩(§9.2).
12. 모호한(결정되지 않은) 피호출자 사이즈 변수(§8.4).
13. 플로우 호출 그래프에서의 직접 또는 상호 재귀(§9.4).

## 10. 예시 (Examples)

다음 적합한 예시들은 언어를 보여준다. 이들은 비규범적(non-normative)이다.

인자 타입으로부터 사이즈 변수를 추론하는 항등 플로우:

```nn
Bypass(x: Tensor[a, b, c]) =
  x
```

빌트인과 임포트된 연산자를 사용하는 플로우:

```nn
import { Gemm } from "./onnx.nn"

Linear[input, output](x: Tensor[input]): Tensor[output] =
  |> Gemm(Trainable[input, output]('weight'), Trainable[output]('bias'))
```

시그니처 전용 연산자 선언:

```nn
Gemm(a: Tensor[K], b: Tensor[K, N], c: Tensor[N]): Tensor[N]
Concat(x: Tensor[Cx, H, W], y: Tensor[Cy, H, W]): Tensor[Cx + Cy, H, W]
```

모양에서의 사이즈 산술:

```nn
Upsample[sH, sW](x: Tensor[H, W]): Tensor[H * sH, W * sW]
```
